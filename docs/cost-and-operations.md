# 成本与运维结论

[返回首页](../README.md) · [验证结果](validated-findings.md)

**把模型费用、平台费用和工程费用分开，才能形成可用于选型的成本口径。**本研究取得了真实用量、资源采样和账单组件；它们支持费用核算设计，不支持宣布某个平台总成本最低。

## 1. 已记录的模型费用组件

以下为升级/回滚批次中成功任务的**模型用量均价估算，单位 USD**。失败计数保留在原尝试分母中，均价只取成功任务。

| Runtime | Trading：成功/尝试 | Trading 均价估算 | RAG：成功/尝试 | RAG 均价估算 |
|---|---|---|---|---|
| ACA | 3/4 | 0.514308 | 4/4 | 0.003868 |
| AKS | 4/6 | 0.533487 | 3/3 | 0.003995 |
| Foundry | 4/4 | 0.560785 | 3/3 | 0.003981 |

RAG 均价按六位小数展示，精确记录见[结构化摘要](../evidence/verified-findings.json)。三端合计 24 次业务尝试，21 次成功、3 次失败；不能将这组发布验收样本当作生产成功率。

**这些值不是单任务平台账单，更不是 TCO。**真实生成内容与 token 数量也会影响均价，不能据此评价 runtime 的资源效率。

## 2. 成本分账规则

| 成本项 | 应使用的数据 | 本研究的明确处理 |
|---|---|---|
| 模型推理 | 每次 provider 请求和 token usage | 使用用量估算，不冒充 Azure 发票 |
| 平台计算 | App、Job、Pod、节点或 session 的账单与资源窗口 | 资源采样不直接当作计费时长 |
| 公共层 | 网关、存储、镜像、日志和网络费用 | 独立记录，不按成功任务数随意摊派 |
| 空闲 | 确定的无业务窗口及对应账单 | 1,945.125 秒资源观察不转换成精确 idle 账单 |
| 失败与重试 | 所有已接受尝试、未确认请求和后续新尝试 | 保留原分母和未结算预留 |
| 工程投入 | 平台治理与业务适配的实际工时 | 不用代码行数替代工时 |

核算总费用时先检查计费项目，避免将 token 估算重复加入已包含模型费用的 ActualCost。共享成本归集规则应由客户财务与工程团队共同确定。

## 3. 可以直接采用的运维原则

1. **版本绑定先于执行：**提交即确定 runtime 与版本，在途任务不随路由更新迁移。
2. **未确认先协调：**按原任务 ID 读回，禁止对可能已消费的请求盲目重试。
3. **恢复检查副作用：**checkpoint 不只检查最终结果，还检查工具写操作是否重复。
4. **故障定位使用关联链：**任务、版本、原生实例、工具事件和错误码应能一起查询。
5. **预算与账单分开：**额度预留和风险上界是治理手段，不是实际支出。

## 4. 成本结论

本研究支持“分层记账、保留失败、明确责任”的核算方法。完整平台成本需要客户自己的负载窗口、基础设施归集规则与工程工时；本报告不输出缺少这些输入的总成本排名。
