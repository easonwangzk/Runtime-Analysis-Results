# 实验方法与结果口径

[返回首页](../README.md) · [结果](validated-findings.md) · [证据索引](evidence-index.md)

**同一业务、明确输入、原生执行、实际结果验收。**平台配置存在、接口返回成功或镜像启动成功，都不是业务完成的替代证据。

## 1. 工作负载

| 对象 | 内容 | 代表的工程问题 |
|---|---|---|
| Trading | 多 Agent 分析、工具调用、真实行情、报告和导出 | 长流程编排、事件、结果交付与版本发布 |
| 商品 RAG | 固定 200 商品、CLIP 编码、Chroma 检索与模型回答 | 检索服务、模型/索引加载和在线响应 |
| 工具会话与机制探针 | 五种编程模型、工具与历史，以及固定故障和计算任务 | 框架接入、恢复、权限、执行边界与故障定位 |

研究比较运行架构，不评价股票收益、模型智力或检索算法优劣。

## 2. 三类结果分别记录

| 类型 | 模型和输入 | 用途 |
|---|---|---|
| 较新的真实业务 | 真实模型；Trading 使用真实行情，RAG 使用真实索引 | 确认业务执行与结果交付 |
| 确定性机制探针 | 固定模型操作；相关恢复/隔离/超时探针 provider 请求为零 | 精确观察 checkpoint、权限和故障处理 |
| 历史回放与早期真模型批次 | 保留各批输入、版本和原始分母；早期 Trading 行情固定 | 解释行为并保留原始观测，不补写较新批次 |

每个批次绑定输入契约、来源、镜像或版本、原生任务和业务回执。原同区域实验与后续 AKS 跨区域恢复实验分开；资源形状、镜像、缓存与宿主条件没有强行合并。

## 3. 判定与统计规则

成功要求实际业务结果满足固定验收。失败保留明确错误；请求可能已发生但结果无法确认时，保留未确认记录，并按原 ID 只读协调。后续新任务成功不覆盖旧任务。

“15 格框架验收”指每种实现/runtime 一组真实两轮会话；“9 个业务组合”指每个组合至少有一个合格成功回执。两者都不是长期可用性指标。

恢复中的 27/23 是确定性探针的模型操作计数，不是付费模型请求或 token 节省率。30 分钟状态保留依赖应用私有持久存储，不推导容器 RAM、平台 HOME 或物理实例保留。

延迟与费用只有在输入、资源、计时与计费范围一致时才能横向比较。本公共版本不发布稳定 P95、生产 SLA、综合性能排名或完整 TCO。

## 4. 证据发布方式

公开内容采用字段白名单：发布聚合计数、业务验证结果、机制指标、模型用量估算和来源文件 SHA-256。任务 ID、资源地址、订阅/租户/身份标识、原始输入、响应、日志和凭据均不发布。

SHA-256 用于版本追溯和核对来源字节，不独立证明实验结论。原始证据和复现代码保留在私有研究环境；外部读者可以核查公开摘要的数字一致性与报告口径，但不能仅凭本仓库完整复现实验。

## 5. 实验结果与选型指导分开维护

真实执行结果、计数与来源哈希在公开证据摘要中维护；决策树与场景指南是依据公共产品/架构资料和这些结果形成的技术建议。更新选型表达不新增云实验，不将示例场景记为成功任务，也不提升原 P1–P10 判定。

新场景的服务组合需要客户自己的输入、权限、目标区域和交付条件。VM 与其他计算服务用于说明更广的选型范围，不加入本研究三端结果分母。技术指导的公共来源见[证据索引](evidence-index.md)。
