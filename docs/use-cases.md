# 场景与服务组合指南

[返回首页](../README.md) · [技术决策树](architecture-decision.md) · [实验结果](validated-findings.md)

**按任务、数据与控制要求组织场景，不按行业标签直接分配 runtime。**这里给出公开架构资料与既有实验支持的设计建议，不表示下列业务产品均已实现。

## 1. 场景画像

| 场景 | 典型任务与数据 | 优先评估的路径 | 必要配套 | 现有实验关联 |
|---|---|---|---|---|
| **在线检索与服务助手** | 查询知识或商品，按授权调用下游接口 | 已有容器接口可从 ACA 开始；需要托管 Agent 会话时评估 Foundry | 身份、检索范围、结果来源、工具权限与超时 | R 的真实检索/文本回答；P6/P7 |
| **长流程研究与报告** | 多步工具调用、分析和报告交付 | 根据控制和协议需求在三端选择，不以“任务长”直接决定平台 | 持久任务账本、checkpoint、副作用幂等、结果与版本绑定 | T；P3/P9 |
| **受控工具与开发辅助** | 执行经过授权的计算或工具，诊断失败 | 先设计执行信任边界；需要 Kubernetes API 时评估 AKS，其他路径按契约选择 | 凭据隔离、工作目录、输入范围、资源限制与退出确认 | S；P4/P8 的固定工具与计算探针 |
| **多业务 Agent 托管** | 多个业务接入共同运行入口并独立发布 | 需要 Agent 对象与版本机制时评估 Foundry；已有容器平台则评估 ACA/AKS 复用 | 业务身份、配额、工具注册、版本与回滚契约 | P1/P7/P9 |
| **事件驱动与有限时长处理** | 响应事件、持续消费或处理一个有限任务后退出 | 在 ACA App/Job 或其他事件/计算服务之间按任务形态选择 | 队列、幂等、取消/截止、失败协调与结果持久化 | 公开 App/Job 设计；不是本研究新完成的完整执行矩阵 |
| **多组织或敏感数据应用** | 多个组织的数据和工具，或具有严格访问要求的资料 | 先验证区域、数据、身份、隔离与审计要求，再选择满足条件的候选 | 租户范围、私网、最小权限、数据保留/删除与独立安全评估 | P4/P6/P7 提供部分机制证据，不构成完整多租户或合规认证 |

同一产品可能同时属于多个画像。例如在线查询可以触发一个后台研究任务，研究任务又调用私有工具；应分别设计前端/网关、Agent worker 与工具执行组件。

## 2. 将场景转成可验收的契约

### 在线检索与服务助手

先区分检索、推理和业务写操作。对知识或商品结果检查其来源与访问范围；对工具操作检查实际用户权限。入口服务稳定并不代表检索或 Agent worker 已完成任务。

已有 API 与容器可以采用 ACA 承载；当产品希望使用托管会话与 Agent 版本机制时，评估 Foundry 协议与所需交互是否匹配。需要 Kubernetes 专属控制时，再将相关组件纳入 AKS。

**验收重点：**授权查询、受限工具、超时、任务结果与重连读回。R 提供真实商品检索和文本回答证据，不替代企业文档的逐项权限过滤验收。

### 长流程研究与报告

区分模型调用、工具副作用与步骤状态。客户端断开、worker 终止和协调服务重启分别处理；新版本不应改变在途任务的原绑定。

**验收重点：**中断后是否从定义的步骤恢复、工具写操作是否重复、结果能否导出，以及升级/回滚后的任务与版本是否一致。T 与 P3/P9 支持这些工程契约，checkpoint 指标来自确定性机制探针。

### 受控工具与开发辅助

固定可信工具、动态模型生成代码和用户提交程序是不同信任等级。先确定执行域、允许的输入与出网范围，再选择承载服务；更换 runtime 本身不能完成安全设计。

**验收重点：**最小凭据、任务/工作区绑定、独立执行边界、资源限制、异常退出和结果读回。本研究的 P4/P8 验证固定工具与计算，不认证任意代码执行或强安全沙箱。

### 多业务 Agent 托管

明确哪些能力由平台提供，哪些由应用治理。Foundry 的 Agent identity/version/session 可以作为设计对象；ACA/AKS 可以承载自有任务协议。下游数据权限仍按实际执行身份和业务范围配置。

**验收重点：**业务身份是否被正确绑定、发布能否隔离版本、失败任务是否保留，以及账单是否能解释。P1/P7/P9 是相关机制证据，不意味着本研究交付了完整商业托管平台。

### 事件驱动与有限时长处理

持续运行并消费输入的服务，与处理一个有限任务后退出的 Job 不同。ACA 官方设计分别提供 App 与 Job；如果组件更适合其他计算形态，应按公开计算选型资料继续比较。

**验收重点：**接受与执行时点、去重、失败重试、结果未确认时的协调，以及资源窗口。此处是服务设计建议，不新增一组已完成的并发或取消验收。

### 多组织或敏感数据应用

应用租户不是单个用户，也不等同于 Microsoft Entra tenant。明确共享/独占范围、身份、存储、工具和运维访问，再判断计算服务与区域是否满足要求。

**验收重点：**跨范围拒绝、最小权限、数据流向、保留与删除、审计关联和故障处置。选择某个服务名字不构成合规结论；应用 ACL 结果也不能代替租户隔离的完整评估。

## 3. T/R/S 如何帮助客户验证自己的方案

| 实验对象 | 可复用的验证思路 | 不能直接替代的客户验收 |
|---|---|---|
| **T** | 长流程、工具调用、报告、在途版本、升级与回滚 | 客户业务正确性、生产成功率和服务目标 |
| **R** | 检索/生成分层、固定输入、数据加载与结果展示 | 企业内容权限、目标数据量和负载 |
| **S** | 框架工具与历史、checkpoint、权限、工具超时和退出 | 任意代码隔离、完整平台行为或行业认证 |

这些映射将实验结果用于设计验证方法，不把实验探针当作所有场景都已上线的证明。
